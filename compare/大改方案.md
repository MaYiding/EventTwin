# 大改方案：三层升级蓝图（表示适配 × 判别蒸馏 × 双层聚类）

> 2026-09-30。承接《过分裂调研报告》的小改/中改结论。本方案回答："如果不怕改得多、要一开始就做最好的，哪些环节值得动大手术？"每个模块给出文献依据（含数字）、我们自己的数据支撑、工程步骤、风险与验收标准。

## 0. 总览与设计原则

**判据**：一个大改模块入选，必须同时满足——(a) 针对我们实测的最弱环节；(b) 文献有量化证据（不是概念性先进）；(c) 有免费或廉价的训练数据来源；(d) 不推翻已验证为长板的部分（六段主线、断言账本、证据链、Jev 判定协议、attach 精度 1.0）。

**三层结构**（自底向上，前一层是后一层的地基）：

| 层 | 大改模块 | 针对的实测短板 | 核心文献证据 |
|---|---|---|---|
| L1 表示层 | 同事件对比适配（微调 embedding-8b） | R1 召回未相遇 42%；通用 embedding 判定面"全拒型"（本地评测 13 真实体全 <0.5） | LFEvent (WSDM 2026)：任务适配表示 ARI .90 vs 通用表示 .12-.32；Databricks 2025 领域微调实证 |
| L2 判别层 | Jev 蒸馏到本地判别器 + 分层推理 | 判别延迟 0.8s/次、API 成本、规模化受限（18k 提及全量判别要 30-60 分钟） | SECURE (ACL 2024) SLM+LLM 协同 SOTA；DecomposeRL (2026) LLM judge→小判别器成本 10×降；CohTP (ACL 2026) 选择性干预 |
| L3 聚类层 | 在线判定 + 周期全局 canonicalization（correlation clustering） | R5 同日隔离 42% + 传递性不一致无全局修复 | 2508.08272 在线+按天批合并 AMI .40→.57；SBBD 2025 置信度修边 98.1% 删对；ICML 2025 / NeurIPS 2023 可扩展相关聚类算法 |
| — 基础设施 | **不动**（SQLite/自研ANN/队列） | 非质量瓶颈：4597 篇规模暴力余弦毫秒级、单写者无竞争 | 架构文档 Kafka/OpenSearch 映射本就是单机模拟，升级引擎不改变质量指标 |

三层合力后的量化预期：**过分裂 0.433 → 0.05-0.15，attach 精度保持 ≥0.95，判别吞吐 ~100×（0.8s→ms 级），API 成本 →~5%，全量语料可日级全量重跑**。

## 1. L1 表示层：同事件对比适配（地基，优先做）

### 1.1 为什么值得大改

实测证据链：
- 通用 embedding 的相似度只测"主题相近"，不测"同事件"——我们的五模型评测里 embedding 实体核对是"全拒型"（13 个真实体相似度全 <0.5）、事件核对 AUC 0.43；
- 过分裂 R1（42%）的直接机理就是"质心/ANN 找不回对方簇"——两个同事件簇的事件卡向量距离不够近；
- [LFEvent（WSDM 2026，本地 S03 精读）](https://arxiv.org/)的对照数字最尖锐：**同一聚类任务，通用 BERT/SBERT/CLIP 直接聚 ARI .12/.23/.32，任务对比适配后 .90**——表示层不对齐，下游一切相似度操作都在错误的几何里做。其"可落地动作"一节（本地精读原文）明确建议了本路线：正对=同源转载对/同 EventMention 增强视图，一期可不用 MLLM 增强。
- [Databricks 2025](https://www.databricks.com/blog/improving-retrieval-and-rag-quality-embedding-model-fine-tuning)与 HF 2026 实践指南：领域微调 embedding 对检索精度提升显著且一天内可完成；[SeInEvent（AAAI 2026，本地 S02）](https://ojs.aaai.org/)进一步证明增量表示学习（蒸馏+对比交替）能在流式场景持续保持表示质量（NED 10 年流上 AMI .81-.97）。

### 1.2 方案

**训练数据——全部免费，来自现有库的"已被验证的判定"**：

| 对类型 | 来源 | 标签 | 预计量级 |
|---|---|---|---|
| 正对 1：同簇成员框架对 | 高置信 attach（unique_id_anchor / bypass / judge≥0.9）的簇内成员两两 | 同事件 | 数万 |
| 正对 2：转载对 | 同 lineage_group 的不同文档版本提及 | 同事件 | ~1500 |
| 正对 3：Jev 高置信簇对 | p_same ≥0.9 与 judge same_event 概率分布 | 同事件 | 数千 |
| 负对（hard negative 关键） | 同实体×同类型×时间窗重叠但 Jev 判异（C 维度 0.5 以下）+ 不同新建簇对 | 不同事件 | 数万 |

hard negative 是成败关键：LFEvent 消融与 SBBD 2025（真假匹配均分 0.936/0.729 难分）都表明"主题相近但非同事件"的负例决定判别面。我们库里这类对天然存在（94% 单成员簇 = 海量近似负例）。

**微调方式**：qwen3-embedding-8b + LoRA（PEFT），InfoNCE 对比损失，混合 10-20% 通用数据防灾难性遗忘；框架用 sentence-transformers 3.x 的 Matryoshka/对比训练流水线。训练在 902 容器那台 GPU 机或 CI runner 上单卡可跑（4096 维 8B 模型 LoRA，数万对在几小时内）。

**评估集（先建再训）**：从 C 维度题面扩展为固定 500 对"簇对同事件检索"测试集（Jev 判定为金标 + 人工抽检 50 对），报告适配前后的 retrieval accuracy@1 与分离度（正对均值-负对均值）。

### 1.3 收益、风险与验收

- 收益：R1 的直接解法（召回相遇率上升）；S_semantic 特征更准；事件卡 ANN 通道质量上升；L3 的 blocking 候选生成受益。
- 风险与对策：灾难性遗忘（混通用数据+LoRA 小秩）；重放一致性（向量缓存按模型版本键隔离，全量重嵌一次 ~分钟级）；训练对噪声（只用 ≥0.9 高置信对，丢弃灰带）。
- 验收：分离度提升 ≥0.15；召回相遇率（新建簇对中"对方簇在候选池出现"比例）从当前水平显著上升；C 维度过分裂率开始下降。

## 2. L2 判别层：Jev 蒸馏 + 分层推理（速度与规模化）

### 2.1 为什么值得大改

- Jev 判定质量已验证（attach 精度 1.0、事件核对 1.0），但它是一次 0.8s 的 OpenRouter API 调用——18k 提及全量判别 30-60 分钟、有真金成本、依赖外网。这决定了判别只能用在"灰区"（当前 418 次/全量），无法承担 L3 需要的万级簇对全量打分。
- [SECURE（ACL 2024 Main）](https://aclanthology.org/2024.acl-long.164/)证明协同路线是 CDECR SOTA：SLM 微调学到"简单共现"之外的判别力，LLM 贡献上下文理解，协同优于任一单独使用；
- [DecomposeRL（2026）](https://github.com/dipta007/DecomposeRL)给出精确的工程范式：Qwen3-32B 的 LLM judge 精准但吃掉训练期 GPU 成本 → 蒸馏成 8 个 ModernBERT-large "tiny judges"，**成本 10×降**且保持判定质量；
- [CohTP（ACL 2026，本地 A01）](https://arxiv.org/)的选择性干预结论兜底：只对低质量 32% 送 LLM 复判优于全量 LLM 干预（全量反而 -3.7 分）——分层推理不是妥协而是最优形态。

### 2.2 方案

**教师**：Jev（不变，升格为"教师 + 终审 + 仲裁"）。**资产复用**：我们已有 11188 条 Jev 判定缓存（p_same 排序分布、灰区 judge 双问、评测五维），输入输出完整可重构为训练集——这是整个大改里最值钱的现成数据。

**学生**（两个候选，先做 a）：
- a. **双塔判别头**（DecomposeRL 路线）：L1 适配后的 embedding 编码两个框架/事件卡 → 拼接 + 交互层 → sigmoid 同事件概率。参数量小、毫秒级、可批量 GPU 推理；训练对直接复用 L1 的对数据 + Jev 概率做软标签（回归蒸馏，保留教师的置信度信息——SBBD 2025 证明置信度可分带）。
- b. qwen3-8b LoRA 指令式判别（生成式概率抽取）：能力上限更高但延迟秒级，作为 a 不达标时的备选。

**分层推理协议**（替换现在的"rerank 特征 + 灰区 judge"两级）：

```
全量对（提及×候选、簇×簇） → 学生判别器打分（本地 GPU，ms 级）
  p ≥ 0.9   → 直接采纳（对齐评测 conf≥0.8→96.8% 分带）
  0.3-0.9   → 升 Jev 复判（教师终审，约占 10-30% = CohTP 选择性干预区间）
  冲突/合并仲裁、novel 事件边界 → 必须 Jev（保铁律：判别权归 Jev 的精神）
```

### 2.3 收益、风险与验收

- 收益：判别吞吐 ~100×（18k 提及全量判别从 30-60 分钟 → 秒-分钟级）；API 成本 →~5%（只灰带升审）；L3 的万级簇对全量打分成为可行；断网/离线可跑。
- 风险与对策：学生精度不足（分层设计保底：灰带全升审，学生只承担"高置信快速通道 + 候选打分"，最终判定权仍在教师）；蒸馏数据分布偏（缓存覆盖 p_same/judge/评测三任务，且持续新增——Jev 每次灰区调用都在免费扩充训练集，形成数据飞轮）。
- 验收：shadow 模式并行跑 2 周（学生与 Jev 同题对判），一致率 ≥90% 且分歧例人工复核无系统性偏差；全量重跑后五维评测不退化。

## 3. L3 聚类层：在线判定 + 周期全局 canonicalization（质量闭环）

### 3.1 为什么中改不够、大改做什么

中改（按天 merge pass）是增量对判：每对独立判定、逐对合并。三个残留问题：同日的传递性不一致（A≈B、B≈C、A̸≈C 时先合谁）没有全局解；hub 实体的高簇对密度下贪心合并顺序敏感；只能"并"不能"重排"（成员级 reassignment）。大改把批处理层升级为**周期性全局 canonicalization**：

[2508.08272] 证明在线层必然过早分簇（我们的 R5=42% 同病），其按天批合并把 AMI .40→.57；[EDC（EMNLP 2024）](https://arxiv.org/abs/2404.03868)的 canonicalization 是"全量簇对检索 + LLM 终判 + 一轮即收敛（二轮边际 <0.5%）"；[SBBD 2025](https://sol.sbc.org.br/index.php/sbbd/article/view/44035)证明成对判定的传递性不一致必须也只需在分量级修（42 分量全修复、52 删边 98.1% 删对、置信度做边权）。SBBD 用 ILP 不可扩展——这正是经典相关聚类近似算法的用武之地：[ICML 2025 beyond-pivot](https://icml.cc/virtual/2025/poster/45406)、[NeurIPS 2023 单遍半流式 (3+ε)-近似](https://proceedings.neurips.cc/paper_files/paper/2023/file/149ad6e32c08b73a3ecc3d11977fcc47-Paper-Conference.pdf)、[ESA 2024 综述（1.44-近似与 local-search 1.84-近似）](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ESA.2024.1)——pivot 算法 O(n·d) 级实现简单，万级簇图的局部搜索分钟级。

### 3.2 方案（批处理层的完整流程）

```
周期触发：每语料批末 / 每日（对齐 2508.08272 的按天批次）

P1 候选对生成（blocking，L1 成果直接受益）：
   同类型 × 实体交集 ≥1 × 事件时间窗重叠/间隔≤gap
   ∪ 适配后事件卡向量 top-k 近邻（k=20）
   ∪ "同日创建"簇对（R5 专项，时间片隔离的镜像修复）
P2 全量打分（L2 学生判别器，ms/对；万级对分钟级）
P3 图构建：节点=簇，边=学生概率 - 0.5（正=同、负=异，SBBD 置信度边权）
P4 correlation clustering（pivot + local search 近似；传递性目标显式进目标函数，
   不做隐式连通分量闭包——铁律"不传递闭包"的数学化表达）
P5 差分执行（与在线层现状 diff）：
   - 合并提案 p≥0.9 → 自动 merge_clusters（版本化、redirect、可撤销——机制已有）
   - 0.5-0.9 → 人工队列（Web 归类决策面板已有）
   - 成员重挂（reassign）提案 → 同样分带，留痕走既有 resolution_decision 表
   - 全量派生层重建：质心/事件卡/向量/BM25（我们的派生层架构本来就支持随时重建）
P6 审计留痕：每轮 canonicalization 的输入图、边权、决策、前后簇对照全部落表
```

关键设计决策：**在线层与批处理层共用同一套判定协议与留痕格式**（Jev state+questions 结构不变），在线层保持"模拟在线"语义（重放一致性），批处理层是显式的、可重放的、带版本的修正过程——不改任何铁律，只是把"簇间合并仅人工"升级为"高置信自动 + 灰带人工"（与 high_confidence_bypass 之于判别器完全同构的先例）。

### 3.3 收益、风险与验收

- 收益：R5（42%）日尾全救 + R1（42%）大半（簇级 blocking 不受提及级截断限制）+ 传递性不一致全局修复；单成员簇占比 94% 显著下降（2508.08272 同类场景合并后离群故事占比大幅下降）。
- 风险与对策：合并错误传播（分带 + 版本化可撤销 + 每轮后跑五维评测做回归门禁）；重放语义（批处理轮次号进 manifest，每轮确定性重放）；算力（pivot 实现万级节点分钟级，无风险）。
- 验收：C 维度过分裂率 0.433 → ≤0.15（目标 ≤0.10）；A 维度 attach 精度 ≥0.95 不退化；新增指标"canonicalization 轮召回率"（金标簇对被提案覆盖比例）≥0.8。

## 4. 不做的部分（明确排除，防过度工程）

| 候选 | 排除理由 |
|---|---|
| 换 Neo4j/专业向量库/真 Kafka | 不是质量瓶颈（万级向量暴力余弦毫秒级；单写者无竞争）；架构文档的 Kafka/OpenSearch 映射本来就是单机模拟设计，升级只改吞吐不改质量 |
| micro/macro 流式重构（DBSTREAM/TextClust 路线） | 推翻现有时间片并行架构，收益不明（2508.08272 的在线层 AMI 仅 0.16-0.40，其价值全在批处理层——我们直接做批处理层即可） |
| 训练式图精化（CohTP EA-GNN 类） | 需要时间关系标注数据与训练基建；其增益（时间一致性）我们已用硬过滤+显式时间特征覆盖（R3=0 证明够用） |
| 多模态（SeInEvent/LFEvent 的 VQA 增强） | 我们是纯文本语料；其思想（增强视图做正对）已吸收进 L1 的正对构造 |
| ILP 全局最优 | SBBD 作者自认扩展性未解；pivot+local search 在我们的规模上近似质量足够 |

## 5. 落地顺序与里程碑

| 阶段 | 内容 | 工作量 | 门禁（不过不进下阶段） |
|---|---|---|---|
| M0 | 小改 S1-S3 + 中改 merge pass（已批准，先拿确定性收益） | 1-2 天 | C 维度降到 ≤0.30 |
| M1 | L1 评估集构建 → 对比适配训练 → 离线评估 | ~1 周 | 分离度 +0.15、召回相遇率升 |
| M2 | L2 学生判别器训练 → shadow 并行 | 1-2 周 | 与 Jev 一致率 ≥90% |
| M3 | L3 批处理层 dry-run（只出提案不执行）→ 分带放开 | 1-2 周 | dry-run 提案精度 ≥0.9（人工抽检） |
| M4 | 全量重跑 + 五维评测 + 两线对比 v3.2 报告 | 2 天 | 过分裂 ≤0.15 且 A/B/D/E 不退化 |

全程验证闭环复用现有资产：`jev_judge.py` 五维（金标判定器就是 Jev——注意 M2 后需引入"人工抽检"防教师自我循环偏差）、`oversplit_autopsy.py` 根因剖析、`fingerprint.py` 重放一致性。

## 6. 一句话结论

大改的正确姿势不是推翻六段主线，而是**给它换三个器官**：给召回换上"同事件对齐的表示"（L1），给判别换上"本地毫秒学生 + Jev 教师终审"的双层心脏（L2），给聚类补上"周期全局 canonicalization"的闭环大脑（L3）——每一层都有本地实证的病因、文献的量化证据、免费的训练数据（11188 条 Jev 缓存是飞轮起点）和现成的验收闭环。
