# L1（表示适配）× L2（Jev 蒸馏）专项调研与决策报告

> 2026-09-30。方法：三路子 Agent 深挖（Jev 模型本体 / embedding 微调数据效率 / 判定蒸馏工程实证）+ 本机实测（Jev 真实延迟成本并发、缓存数据资产盘点、训练资源摸底）。全部结论有出处或实测数据。

## 一、真机实测数据（一切论证的地基）

### 1.1 Jev 实测（OpenRouter，2026-09-30，我们生产同款请求）

| 指标 | 实测值 |
|---|---|
| 单发延迟 | p50 **0.46s**（min 0.37 / max 0.60，国内→OpenRouter） |
| 单次成本 | **$0.00004**（951 input + 81 output tokens；官方定价 $0.042/M 输入、**输出免费**） |
| 并发吞吐 | 8 并发 15.3 req/s；16 并发 10.1；32 并发 16.8（**~15 req/s 附近饱和**，官方限 40 req/s、100K tok/s，实测未触发 429） |
| **全量成本真相** | 我们 4587 篇全量跑一遍（10658 次 p_same + 493 次 judge + 扩池）≈ **$0.5**；按每天 3 万次判定 ≈ **$36/月、$430/年** |

### 1.2 数据资产盘点（训练数据"现在就有多少"）

| 来源 | 规模 | 用途 |
|---|---|---|
| p_same 分布缓存 | 10658 次请求 → **可重构 167,653 对**（945 正 + 166,708 负） | 蒸馏/对比训练对，负对免费海量 |
| attach 决策 + 多成员簇 + 转载组 | 699 attach + 528 多成员簇（簇内正对矿）+ 2851 转载提及组 | 正对来源（正对是稀缺方，约数千） |
| 定向补标（Jev 批量） | C 维度同款 SQL 批量生成"同实体+同类型+时间重叠"疑似对 → Jev 打标 | **几千次调用 ≈ $0.1，补几千高质量正/难负对** |

**关键结论：正负对结构完全反转了"标注成本"叙事——负对免费无限，正对虽稀缺但可用 Jev 以 $0.1 量级定向补齐几千对。高质量人工标注不是必需品。**

## 二、Jev 模型深挖（调研要点）

- **是什么**：TypeSafe（前 OpenAI RLHF 共同发明人创办，$40M 种子轮）2026-09-15 发布的 System One 判定模型。**非自回归**：所有候选答案在一次前向中并行采样（"generates all outputs in a single query"），所以快且输出免费；输出被约束在请求预定义的 schema 内，数学上保证无幻觉。训练用 **RLCD**（校准决策强化学习，与 RLHF/RLVR 并列的第三种后训练范式）+ **全合成数据**。官方不披露内部架构（外界推测为多模型/路由复合系统）。
- **能力边界（jaggedness 官方九条）**：字面化阅读、数学计数、日期比较、多跳推理、大 state 的 context rot、对抗内容不设防、文本生成（不能生成，串 choice 生成又慢又差）。**中文：官方明说"英语最佳、中文精度较低需自测"——但我们的实测中文极好（事件核对 1.0 / 实体核对 0.966 / 层级分类 0.931），这条边界对我们不构成限制。**
- **校准**：组级校准（说 0.8 时同类组约 80% 成真）；第三方评测 ECE 0.144（对比 Laya 0.213）。同一输入重复调用概率轻微波动（0.79 vs 0.84）——阈值应设带不设点（我们已这样用）。
- **风险**：① 定价疑似补贴（官方 FAQ 自设"是否补贴"问题，可持续性未承诺）；② 版本会迭代（1.13 是当前唯一版本，jev-latest 别名会漂移——我们 pin 了日期快照，对）；③ 无 LoRA/私有化选项，企业 ZDR 需谈。
- **免费的替代通道**：`typesafe/jev-router` 完全免费、1M 上下文（自动路由最优推理强度）——可作开发/压测通道。

## 三、L1 表示适配：资源 / 基础模型 / 标注量 的完整回答

### 3.1 需要多少高质量标注？——不需要人工标注，弱监督飞轮就够

文献实证谱系（数据-效果曲线是对数型，几千对已在陡增段）：

| 训练对 | 实证效果 | 出处 |
|---|---|---|
| 5 对 | 专利检索 +6-14% MAP | ACM 2026 |
| 每类 8 个 | SetFit 对比学习≈全量微调 | arXiv:2209.11055 |
| 几百对 | 领域检索 +5-8pp | Databricks |
| 1k-3k | sbert 官方"小样本"场景 | sbert.net |
| 1.4 万合成对 | e5-mistral-7B（纯 GPT-4 合成=当期 SOTA） | arXiv:2401.00368 |
| 500 篇文档合成 | NDCG +10.9%、Recall 0.751→0.951 | NVIDIA/HF |

**我们的量级**：现有 945 正对 + 补标后数千正对 + 5 万抽样负对，落在"工业充分区间"（Databricks/NVIDIA 案例同量级）。**Qwen3-Embedding 官方监督阶段 1900 万对里 1200 万是 Qwen3-32B 合成的，并用 cos>0.7 过滤——Jev 置信度做过滤信号是同一配方。**

成败关键不是数量是**负例质量**：随机负例会让效果低于不微调的基线（CLP 实测 52.9 vs 55.9）；必须 hard negative（同实体同类型异事件——我们库里免费海量）+ **margin 假负例过滤**（负例相似度 > 正例-0.1 的丢弃，Qwen3/NVIDIA/SWIFT 三家官方同款做法；我们的"同实体同类型"负例恰是假负例高危区，用 Jev 复核负对，成本 $0.1 级）。

### 3.2 什么基础模型？

| 候选 | 参数 | C-MTEB | 结论 |
|---|---|---|---|
| **Qwen3-Embedding-8B（现用）** | 7.57B | 73.83 | **主线**：基础设施已在（vLLM 热加载 LoRA），LoRA 后规模优势保留 |
| Qwen3-Embedding-4B | 3.8B | 72.26 | 性价比备选：与 8B 差 1.6 分，而领域微调增益 5-10pp 远大于此——做对照实验 |
| BGE-M3 / Conan | 0.56B/0.33B | — | 仅当训练资源极度受限 |

LoRA vs 全参：sbert 官方实证 LoRA(r=64) 与全参差 0.2pp，adapter 仅 2% 参数——我们的语义对齐任务正是 LoRA 最佳适用类。**8B 已在 902 容器 vLLM 上跑，LoRA 热加载零部署成本。**

### 3.3 需要多少资源？

- **训练**：8B + LoRA + 5 万对 + max_len 512 ≈ **单卡 A100 40GB，3 小时-1 天**（锚点推算：e5-mistral 7B LoRA 180 万对=576 V100 时，我们 1/36 数据量）；24GB 4090 需 QLoRA 1-3 天；配 CachedMultipleNegativesRankingLoss（梯度缓存，小卡跑大有效负例 batch）。**一次性 GPU 成本 $3-10（租用）或内网错峰。**
- **重嵌**：全量向量重算一次 ≈ embedding-8b 分钟级（已有实测吞吐）。
- **人工投入**：数据构造脚本 1 天 + 训练评估 1-2 天；**高质量人工标注为 0**（金标只用于评估，见 §五）。

## 四、L2 Jev 蒸馏：数据量 / 学生模型 / 值不值的完整回答

### 4.1 先给结论：按"省钱"论证——不成立，彻底推翻

实测账：全量判定 $0.5/遍、$36/月。蒸馏一次性训练 $10 + 工程 1-2 人周 + 服务面。**API 年成本 $430 < 一周工程人力成本。为省钱蒸馏是伪命题**（这正是用户直觉"Jev 成本确实挺低"的定量确认）。

### 4.2 但按"效果与使能"论证——三个真实价值

1. **延迟 100×**（0.46s → GPU 2-5ms / CPU 30-80ms）：串行链路（L3 万级簇对全量打分、在线判别的实时路径）从小时级到秒级。这是 **L3 的使能器**——没有本地判别器，L3 的 correlation clustering 只能用 Jev 分批跑（15 req/s 下 10 万簇对=1.9 小时/轮，可接受但难做实时）。
2. **吞吐与离线**：15 req/s → 数千 req/s，无外网依赖。
3. **版本确定性与风险对冲**：Jev 定价疑似补贴、版本会漂移；本地学生冻结权重，判定行为可复现（这正是我们"重放逐字一致"铁律的最彻底实现）。

### 4.3 技术可行性：实证充分，且我们的任务域恰好是最有利场景

| 案例 | 教师→学生 | 数据量 | 效果 |
|---|---|---|---|
| **SECURE（ACL 2024，事件共指=我们的任务域）** | —→ RoBERTa-Large 355M | ECB+ 6.8k 提及 | **微调 355M 反超 GPT-4 prompting 10-81 个 F1 点**（GVC/FCC 上 GPT-4 被截断搞崩到 10.2/6.1） |
| MiniCheck（EMNLP 2024） | GPT-4 → DeBERTa-v3 400M | **1.4-3.6 万合成标签** | ≈GPT-4 判定水平，成本 1/400 |
| DecomposeRL（2026） | Qwen3-32B → ModernBERT-large 头 | 1.2k-25 万 | 域内 -0.5pt，judge 成本 -80% |

**SECURE 是决定性证据**：窄域事件判定上，几百 M 微调模型碾压通用大模型 prompting——"专用模型必须质量够高"的担忧恰好被这个实证回应：我们的数据（Jev 高置信弱监督）比 SECURE 用的标注更便宜且规模相当。

### 4.4 学生模型选型

| 候选 | 参数 | 中文 | 评价 |
|---|---|---|---|
| **bge-reranker-v2-m3** | 568M | 原生多语言，中文强（C-MTEB-Rerank 72.16） | **首选**：本来就是"输入对→相关性分"的 cross-encoder，改"事件对→同事件概率"是同类迁移；官方 FlagEmbedding 微调脚本现成；GPU 2-5ms |
| Qwen3-Reranker-0.6B | 0.6B | 原生 | 备选（decoder 式略慢） |
| ModernBERT-large | 396M | **不支持中文** | 排除 |
| Qwen3-0.6B LoRA | 0.6B | 原生 | 语义鲁棒性最好的备选 |

### 4.5 需要多少数据？

- **v1 验证**：现有 167k 对（下采样平衡后 ~1 万对）即可训练并画"学生-教师一致率"曲线——MiniCheck 用 1.4 万达 GPT-4 水平，我们同量级。
- **达标**：3-5 万对（Jev 定向补标正/难负对，成本 **$1-2**）。
- **软标签蒸馏**：Jev 返回概率，用回归/KL 蒸馏而非硬 0/1（文献：软标签优于硬标签且保灰带校准）——我们天然有概率标签，比 MiniCheck 的合成硬标签起点更好。

## 五、Benchmark：必须自建，方案如下（用户点名的关键项）

**没有benchmark就无法回答"训出来的到底比 Jev 好还是差"——这是整个 L1/L2 的先决投资，一天可建成。**

1. **规模与构成**：1000 对分层金标——明确同事件 300（多来源报道对/转载对）/ 明确异事件 400（跨企业跨类型）/ **灰带 300**（同实体+同类型+时间窗重叠：我们的 C 维度 SQL 直接产出，最考验判定力）。正负带分层是文献标准做法（hard 层决定区分度）。
2. **标注方式（成本 ~$0.5 + 半天人工复核）**：Jev 预标（$0.003/条，文献：比 MTurk 便宜 30 倍且质量更高）→ 人工复核全部分歧与 20% 抽样（双人独立 + 分歧仲裁）。**注意教师噪声上界**：MT-Bench 证据 GPT-4 与专家一致率 85%、人与人之间也才 81%——金标必须以人为准，不能以 Jev 为准（防教师偏差泄漏进 benchmark）。
3. **主指标（对人工金标，不对教师）**：AUROC（免阈值）+ 工作点 accuracy@最优阈值 + **ECE 校准误差**（级联路由依赖概率质量）+ 灰带子集单独报告。次级指标：学生-教师 fidelity（一致率）、时间外推集（训练用 T-30~T-7 数据、测试 T-7~T-1，防分布泄漏——同日新闻同源文本会造成虚高，必须按时间切分）。
4. **误差归因**：学生错误分解为"继承教师错误"（→ 修教师 prompt/换数据）vs"新增错误"（→ 加数据/换模型）——两类错误的修法完全不同。
5. **回归门禁**：模型每次迭代跑固定 benchmark + NanoBEIR 通用回归（防领域微调把通用能力练坏）。

## 六、最终建议（对项目最优的组合）

**核心判断：L1 与 L2 的性质完全不同，不该捆绑决策。**

- **L1（表示适配）：立即做，独立成立。** 它的价值不是替代任何模型，而是修复召回几何——R1（42% 过分裂）的根因是"同事件簇的向量不够近"，这只能靠表示对齐解决，Jev 判定再准也替代不了（判别器见不到候选就是见不到）。数据免费（弱监督飞轮：945 正对 + Jev 补标数千对 $0.1 + 16.7 万负对）、训练便宜（单卡几小时 $3-10）、风险低（LoRA 可回退、NanoBEIR 防回归）。**不做 L1，L3 的簇对 blocking 质量也上不去。**
- **L2（蒸馏）：值得做，但重定位为"L3 的使能器 + 效果上限探索"，不是省钱项目。** 分两步：
  - **第一步（轻量，1-2 天）**：bge-reranker-v2-m3 + 软标签蒸馏，用现有 167k 对训 v1，在自建 benchmark 上与 Jev 正面对决。**判据：AUROC 达 Jev 的 ≥95% 且 ECE 不劣化 → 采用"本地快速通道（|p-0.5|>0.35 直判）+ Jev 终审灰带"的级联**（文献 FrugalGPT 级联把 API 调用压 90%+；这正是用户说的"调置信度参数范围达到接近效果"）；达不到 → 只在 L3 批处理里用，在线判别继续 Jev（$0.5/遍的成本根本不构成压力）。
  - **第二步（视 L3 需求）**：L3 correlation clustering 每轮 10 万级簇对打分需要本地判别器（Jev 15 req/s 要 1.9 小时/轮）；若 L3 日更批处理则 Jev 分批跑完全可接受，本地判别器锦上添花。
- **效果上限的有利证据链**（回应用户"专用必须保证质量高"）：SECURE 355M 微调在事件共指反超 GPT-4 prompting 10-81 分 + MiniCheck 1.4 万标签≈GPT-4 + 我们的教师标签是概率软标签（比二值硬标好）+ 数据飞轮可持续（Jev 每次灰区调用免费扩训练集，新一轮蒸馏成本 $1-2）——**"自训模型 + 置信分带 + Jev 终审"达到接近甚至局部超越纯 Jev 的效果，有充分的实证支撑**。
- **风险对冲**：Jev 便宜疑似补贴（官方未承诺可持续）——本地学生是天然保险；但学生也会过拟合 Jev 的系统性偏差——benchmark 以人工金标为准 + 时间外推集 + 每月漂移检查，构成完整的质量护栏。

## 附：执行清单（建议顺序）

1. **D1：建 benchmark**（1000 对金标，Jev 预标 + 人工复核，半天-1 天）——先于一切训练
2. **D2-D3：L1 数据构造**（正对挖掘 + Jev 补标 + hard 负例 + margin 过滤）+ LoRA 微调 + benchmark 评测
3. **D3-D4：L2 v1**（bge-reranker 蒸馏 167k 对 → benchmark 对决 Jev → 定级联阈值）
4. D5+：回填 L3（簇对 blocking 用 L1 适配向量 + L2/级联判分 + correlation clustering）
